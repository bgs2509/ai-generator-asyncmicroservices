    Ключевая идея¶

    LLM рассматривается не как единый "мозг", а как команда из 8 специалистов, каждый со своей зоной ответственности, инструментами и артефактами.

    Преимущества подхода: - Чёткое разделение ответственности - Явные точки контроля (quality gates) - Предсказуемые результаты - Возможность отката к конкретной роли при проблемах

    Роль 1: Analyst (Аналитик)¶

    Карточка роли¶

    Параметр Значение
    Номер в пайплайне 1 (первый)
    Команда запуска /idea
    Управляющий документ conventions.md, CLAUDE.md
    Доступные инструменты Read, Glob, Grep, Write
    Режим работы Чтение + Запись

    Что делает¶

    Analyst — это "бизнес-аналитик" команды. Он:

    1. Собирает требования от заказчика/пользователя
    2. Задаёт уточняющие вопросы для устранения неопределённости
    3. Формулирует PRD (Product Requirements Document)
    4. Определяет критерии успеха (success metrics)

    5. Находит точки интеграции для новой фичи

    1. Проектирует архитектуру решения на основе PRD и Research

    3. Формирует Implementation Plan с разбивкой на компоненты
    4. Создаёт Tasklist — гранулярный список задач
    5. Определяет контракты между компонентами

    Gate Transition Rules¶

    From Gate To Gate Transition Condition
    - AGREEMENTS_ON Team accepts conventions.md
    AGREEMENTS_ON PRD_READY Analyst completes PRD
    PRD_READY RESEARCH_COMPLETE Researcher completes investigation
    RESEARCH_COMPLETE PLAN_APPROVED Architect plan approved
    PLAN_APPROVED TASKLIST_READY Tasklist created and validated
    TASKLIST_READY IMPLEMENT_STEP_OK All tasks completed
    IMPLEMENT_STEP_OK REVIEW_OK Code review passed
    REVIEW_OK RELEASE_READY QA approved
    RELEASE_READY DOCS_UPDATED Documentation complete
    DOCS_UPDATED SHIPPED Validator confirms all gates

    Формат файла агента (.claude/agents/*.md)¶

    ---
name: Analyst
description: Gathers requirements and creates PRD
tools:
  - Read
  - Glob
  - Grep
  - Write
model: claude-sonnet-4-20250514
---

# Analyst Agent

## Responsibilities
1. Gather requirements from user
2. Ask clarifying questions
3. Create PRD document

## Inputs
- Raw idea from user
- Project context
- conventions.md

## Outputs
- docs/prd/<ticket>.prd.md

## Quality Gate
PRD_READY: All sections filled, no open questions

## Constraints
- Do NOT write code
- Do NOT make technical decisions
- Focus on WHAT, not HOW

    Три уровня AIDD¶

    ┌─────────────────────────────────────────────────────────────────────────────┐
│                      AIDD IMPLEMENTATION LEVELS                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   LEVEL 1: MINIMAL                                                          │
│   ─────────────────                                                         │
│   Что включает:                                                             │
│   • CLAUDE.md (entry point)                                                 │
│   • conventions.md (базовые правила)                                        │
│   • PRD template                                                            │
│   • Tasklist template                                                       │
│                                                                             │
│   Усилия: ~1 вечер                                                          │
│   Подходит для: Личные проекты, quick experiments                          │
│                                                                             │
│   ─────────────────────────────────────────────────────────────────────    │
│                                                                             │
│   LEVEL 2: FULL                                                             │
│   ─────────────                                                             │
│   Что включает (поверх Level 1):                                            │
│   • Все 8 агентов в .claude/agents/                                         │
│   • Все команды (/idea, /plan, /implement, etc.)                           │
│   • Стандартизированная структура docs/ и reports/                          │
│   • Все шаблоны артефактов                                                  │
│                                                                             │
│   Усилия: ~1-2 дня                                                          │
│   Подходит для: Командные проекты, production development                  │
│                                                                             │
│   ─────────────────────────────────────────────────────────────────────    │
│                                                                             │
│   LEVEL 3: STRICT                                                           │
│   ──────────────                                                            │
│   Что включает (поверх Level 2):                                            │
│   • Hooks блокируют действия если gates не пройдены                         │
│   • CI/CD валидация gates                                                   │
│   • Headless automation                                                     │
│   • Автоматические проверки артефактов                                      │
│                                                                             │
│   Усилия: ~1 неделя                                                         │
│   Подходит для: Enterprise, regulated industries, high-stakes projects     │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

    Рекомендации по выбору уровня¶

    Критерий Level 1 Level 2 Level 3
    Размер команды 1 человек 2-10 человек 10+ человек
    Критичность проекта Низкая Средняя Высокая
    Регуляторные требования Нет Частичные Полные
    Время на настройку Минимум Умеренно Значительно
    Автоматизация Нет Частичная Полная
